# 调色工作室

当前版本：`v0.0.1`。

原生 macOS 调色首版，使用 Swift、SwiftUI、Core Image 和 Metal。要求 macOS 14 或更新系统，编译需要 Xcode 工具链。

总体架构与后续实施以 [人像自动精修总体框架](Docs/总体框架.md) 为入口，区分已经实现、独立研究和规划能力；本文件保留操作方式及历史验收记录。

## 启动

在项目目录执行以下命令构建应用，然后在 Finder 中打开生成的应用。

```sh
./Scripts/build-app.sh
open .build/调色工作室.app
```

脚本接受一个输出路径参数。若旧版应用正在运行，传一个新路径可生成独立的新包，避免覆盖运行中的程序：

```sh
./Scripts/build-app.sh /Users/makima/program/Ps/.build/调色工作室-ARW.app
open .build/调色工作室-ARW.app
```

开发运行和测试可使用以下命令。

```sh
swift run --disable-sandbox Ps
swift test --disable-sandbox
```

## 使用

导入 ARW/RAW、JPEG、TIFF 或文件夹，点击底部缩略图选择照片。文件夹导入读取当前层级中的照片；同名的 ARW 与 JPEG 视为同一张照片，只保留 ARW 作为像素源，JPEG 用于人脸与语义分析。只有 JPEG、只有 ARW 或只有 TIFF 也可以直接导入。

右侧可调整曝光、相对色温与色调、高光、阴影、对比度、S 曲线和饱和度。高光滑杆用于压低高光，阴影滑杆用于提亮暗部。双击参数数值可归零。左侧提供五个内置预设，可将当前参数保存为自定义预设，同名自定义预设会更新。

「同步到全部照片」将当前照片的参数和调整图层复制到项目中的每张照片，人物蒙版按每张照片重新生成，之后仍可单张修改。使用「原图」切换前后效果，视图位置与缩放保持一致。可使用加减按钮、触控板捏合、Command＋滚轮连续缩放，点击「适应」显示整张图片，点击「100%」按一个图像像素对应一个屏幕物理像素检查。查看模式下可以拖动图片。

选择导出格式与色彩配置后，可以导出当前照片或整个项目。成片使用「原名-调色」命名，遇到重名自动追加编号。导出任务使用启动时的编辑参数快照。取消导出后，已完成的成片仍保存在目标文件夹中。

项目和预设会自动保存到 `~/Library/Application Support/PsColorStudio/project.json`，再次启动会恢复。项目按原图的绝对路径引用文件，移动原图后需重新导入。

## 图像处理

- 修图以 ARW 原始格式为主：有同名 ARW 时，即使项目记录的是 JPEG，也会自动用 CIRAWFilter 全尺寸解码 ARW（关闭草稿模式、保留 14 位线性信息与 Display P3 宽色域、高光余量更大）作为像素源；配对的相机 JPEG 用于 Vision 人脸检测和 Core ML 语义蒙版，因为它是经过色调映射的 gamma 图像，检测器更稳定。只有 JPEG/TIFF 时直接处理该文件；只有 ARW 时蒙版也回退到 RAW 像素。用 `preferRAW: false` 可强制走纯 JPEG 路径。
- 预览和导出共用白平衡、曝光、明暗、曲线、对比度、饱和度处理链，使用 32 位浮点中间缓冲和扩展线性 Display P3 工作空间。
- 交互预览从全尺寸原图渲染，缩放范围为 2% 到 800%。预览为 8 位色彩管理显示，TIFF 导出为每通道 16 位。
- 导出应用 EXIF 方向并写回正常方向，同时保留像素尺寸和 DPI。横竖旋转时交换宽高和两个 DPI 轴。
- TIFF 使用 LZW 无损压缩，JPEG 使用 0.96 编码质量。JPEG 会有有损压缩，透明像素在 JPEG 导出时以白色合成。
- 可以保留输入 RGB 色彩空间或转换为 sRGB，输出嵌入相应色彩配置。非 RGB 输入使用 sRGB 输出，缺少 ICC 的输入使用系统解码器的默认解释。
- 原图独立保留。成片先写临时文件，成功后移到目标路径，写入失败或取消时清理临时文件。
- 本版导出保留尺寸、方向、DPI 和输出色彩配置。其他拍摄元数据暂未复制到成片。

当前支持手动参数调色、参数预设、参考肤色目标逐张适配和批量同步。逐张自适应基础曝光已可选启用；可编辑控制点曲线属于后续模块。调色参数使用本应用的定义，视觉效果需要结合实际拍摄样片校准。

参考肤色模板已接入应用界面；独立的 `ReferenceMatch` 肤色追色试验程序继续保留，使用方法见文末。

```sh
swift run --configuration release PhotoCatalog \
  --source /Users/makima/program/Ps/100MSDCF \
  --output /Users/makima/program/Ps/PhotoLibrary
```

日期依次使用 EXIF 拍摄时间、EXIF 数字化时间、TIFF 时间。缺少照片日期时，使用 Asia/Shanghai 时区的文件创建时间或修改时间，并在清单中标明来源。以拍摄记录中的当地日期分组。

每天的目录里存放指向源文件的符号链接，包含 ARW 与 JPEG 配对。浏览这些链接时需要连接原图所在的磁盘。文件清单保存在 `catalog.json`，按天统计保存在 `分类说明.md`。加上 `--dates-only` 可只做日期分类。

## 调整图层与蒙版

左侧「调整图层」的加号可添加全图、人物、背景、脸部皮肤、服装、高光和暗部调整。点击图层后，右侧滑杆修改该图层的曝光、白平衡、曲线、明暗和饱和度。点击「基础调色」返回最先执行的全图调整。

图层从列表下方向上方依次执行，支持显示/隐藏、上下移动、删除和不透明度。选择图层后可重命名、切换区域、反相蒙版、设置羽化和高光保护。高光与暗部蒙版提供亮度过渡起止值，选区根据原图亮度生成。高光保护会减少调整图层对原图明亮区域的影响。

混合模式提供「正常」「明度」「颜色」。明度与颜色模式在扩展线性 Display P3 空间计算亮度与色度，用 Metal 算子保留中间高光范围，后续图层可以继续处理这些值。其算法采用本应用的定义。Metal 自定义混合需要 GPU 支持动态库。

「人物提亮＋高光保护」会添加两个可独立微调的示例图层。人物层提亮 0.35 EV，并设置 80% 高光保护，另一层对高光区域降低 0.3 EV。参数用于起步调色，可按实际照片调整。

预览区的「蒙版」显示当前图层的有效黑白蒙版，包含不透明度、反相、羽化和高光保护。该视图用于检查作用区域，导出始终输出调色成片。人物选区使用 Vision 准确模式，并通过原图引导上采样细化边缘。人物蒙版覆盖整个人。脸部皮肤和服装使用独立 Core ML 模型分割，支持画笔修正。

撤销和重做可通过工具栏或 Command-Z / Shift-Command-Z 使用，历史保留最近 40 次操作。调整图层会随项目和自定义预设保存，旧版项目可直接读取。成片导出为合成后的 TIFF 或 JPEG。

本地人物验收可以使用下面的命令，运行 12 张测试照片的蒙版检查和主图全分辨率 TIFF 导出检查。

```sh
PS_TEST_PHOTO_DIR=/Users/makima/program/Ps/PhotoLibrary/测试组/2025-09-29/JPEG swift test
```

## 皮肤与服装独立调色

「皮肤与服装分开调色」会添加两个中性调整图层，并显示脸部皮肤蒙版。选择对应图层后，可以分别调整曝光、白平衡、饱和度等参数。该按钮只创建选区，调色强度由用户决定。

脸部皮肤选区通过人脸检测裁出头部区域，再用 FaceParsing 模型区分皮肤、眼睛、嘴唇、头发等类别，选入皮肤、鼻子、耳部和识别到的脖子。上唇与下唇单独构成「嘴唇」选区，不并入皮肤选区，这样提亮脸部时不会让嘴唇相对变暗。当前范围集中在脸部及邻近耳颈。身体皮肤现在提供基于姿态与肤色色差的独立候选选区，手臂和腿部漏选仍可用画笔补选。

服装模型区分上装、下装、连衣裙和背景，并结合脸部解析结果排除头部。复杂裙摆、印花、薄纱、袖口和遮挡仍可能存在漏选或误选，可以在「蒙版」视图中检查。

在当前图层的「画笔」中选择「补选」或「擦除」，拖动画笔修正选区，Option 可临时擦除。一次完整笔画对应一次可撤销操作。「清除当前图层的画笔修正」恢复自动选区。画笔先作用于原始选区，随后执行反相、羽化、高光保护和不透明度。

批量同步会重新计算每张照片的自动选区，接收照片保留同一图层 ID 下各自已有的画笔修正。自定义预设保存自动选区类型和调色设置，画笔修正保存在每张照片的项目记录中。

模型随应用打包，照片分析和推理在本机完成。模型来源、版本与许可证位于 `Sources/ColorEngine/Models`。初次构建会下载固定版本的 Core ML 模型并验证权重哈希，后续构建复用已准备的模型。独立运行 `swift build` 前可执行 `python3 Scripts/prepare-models.py` 准备模型。

脸部模型使用 CPU/GPU 计算路径，首次推理可能需要等待模型准备。皮肤与服装使用自动解析选区，边界准确性需要结合实际照片和蒙版预览检查。


脸部皮肤图层提供「压低泛红」滑杆，按红色占比对偏红像素适度降低色彩浓度，同时保留线性亮度。该控制与肤色提亮分别调整，作用范围受皮肤蒙版约束，可用于减轻双颊过重的红色。自动颜色选择仍需结合照片检查。

嘴唇图层提供「唇色自然化」滑杆，只把浓暗红往柔和的玫瑰／珊瑚色偏移（暗部偏移更强），不改变亮度；亮度由该图层的曝光滑杆负责，因此唇纹与高光得以保留。嘴唇独立成层，可避免脸部提亮后嘴唇相对变暗。

## 人像修图流程（ARW 优先）

`PortraitRetouch` 是可复现的命令行人像修图流程，使用与界面相同的 ColorEngine、蒙版和调色算子。传入 JPEG 会自动升级为同名 ARW 像素源（配对的 JPEG 只用于检测）；`--jpeg-only` 可强制走纯 JPEG 路径；传入单独的 ARW 或 JPEG 也都能处理。

```sh
swift build --disable-sandbox -c release --product PortraitRetouch

./.build/release/PortraitRetouch \
  --input /Users/makima/program/Ps/PhotoLibrary/测试组/2025-09-29/JPEG/DSC00681.JPG \
  --output /Users/makima/program/Ps/PhotoLibrary/测试组/2025-09-29/成片 \
  --qa /Users/makima/program/Ps/.build/QA \
  --name 自然白皙-ARW \
  --compare-legacy /Users/makima/program/Ps/PhotoLibrary/测试组/2025-09-29/成片/DSC00681-肤色修订.jpg
```

`--candidates` 会生成「肤色候选」与「唇色候选」两张多列对比图而不导出成片；`--skin-ev`、`--redness`、`--lip`、`--lip-ev` 可单独调参；`--overwrite` 覆盖同名成片，默认遇重名自动追加编号。输出为 16 位 TIFF（保留像素源的 Display P3 宽色域）、sRGB JPEG、原图／上一版／新版三方对比图，以及记录最终参数与图层 ID 的 JSON。尺寸、方向和 350 DPI 与输入一致。

DSC00681 的验收参数相对上一版做了如下调整，目的是「自然白而非死白、唇色自然」：

| 项目 | 上一版（肤色修订） | 现行（自然白皙） |
| --- | --- | --- |
| 像素源 | JPEG，8 位 sRGB | 同名 ARW，14 位线性、Display P3 |
| 全图白平衡 | 无 | 相对色温 −600／色调 +15，抵消 ARW 显影偏暖 |
| 脸部皮肤提亮 | 1.05 EV | 0.45 EV |
| 压低泛红 | 0.40（连血色一起压掉） | 0.22（保留红润） |
| 高光保护 | 0.35 | 0.70 |
| 高光／阴影 | 0 / 0 | −0.12（回收高光）／+0.10（提暗部） |
| 皮肤图层不透明度 | 1.0 | 0.92 |
| 嘴唇 | 无独立处理，皮肤蒙版本来就排除嘴唇 | 独立嘴唇选区，+0.16 EV、唇色自然化 0.60 |

上一版把皮肤提亮 1 EV 又强力减红，8 位 JPEG 的高光被推平、丢失纹理，同时嘴唇完全没被调整，于是相对变白的脸显得更暗红。新版用 ARW 的高光余量，把提亮幅度降下来，靠高光回收、暗部提升和保留血色来维持皮肤层次；嘴唇单独成层，只把浓暗红往柔和玫瑰色偏移并用小幅曝光提亮，因此既不暗红也不发灰白。

ARW 的默认显影比相机 JPEG 偏暖，不做补偿时脸颊色相会从 37° 漂到 49°。流程默认加一组轻微的全图色温／色调补偿（作用到背景和服装，不是只改脸），把肤色拉回该人物在测试组中测得的基线，同时不牺牲彩度。用 `Scripts/skin-metrics.py` 对 DSC00681 脸颊采样区量化的结果（相对原图）：

| 指标 | 上一版（肤色修订） | 现行（自然白皙 · ARW） |
| --- | --- | --- |
| 亮度 L* | +20.61（到 80.67，超出该组典型 68） | +8.89（到 68.96） |
| 彩度 C* | −6.78（降饱和，塑料感来源） | −2.00 |
| 色相 h° | ±0.00 | −0.36（36.9°，基线 37.3°） |
| 肤色角 ITA° | +33.68（到 61.18） | +15.60（到 43.10） |
| 亮度区间 p10–p90 | 69–88 | 58–78 |
| 高光溢出 | 0% | 0% |

也就是说，新版在把亮度提升到自然白区间的同时，保住了彩度、色相和明暗层次，而不是靠压平高光换来的「白」。

## 从参考图提取肤色并追色

`ReferenceMatch` 使用本地 Vision 与 FaceParsing 识别面积最大的人脸，排除眼睛、嘴唇、头发和背景，在脸部皮肤中提取 CIELAB D65 的亮度、红绿和黄蓝分量，保存 p10、p25、中位数、p75、p90 和有效采样数。分析时统一转换到线性 Display P3，再转换为 Lab，避免直接比较不同 ICC 空间中的 RGB 数值。

输入底稿使用已显影的 16 位 TIFF；RAW 可先用 `PortraitRetouch` 显影。`--analysis` 用原始 JPEG 生成选区，要求它与底稿转正后尺寸、构图一致。处理不改变照片几何形状，不进行磨皮；追色强度默认 85%。明度通过单调曲线调整，色彩调整按中位数与四分位区间计算，并限制变化幅度。高光、深阴影的色彩调整逐渐减弱。

```sh
swift run --disable-sandbox ReferenceMatch \
  --input /Users/makima/program/Ps/PhotoLibrary/测试组/2025-09-29/成片/DSC00681-自然白皙-ARW.tiff \
  --analysis /Users/makima/program/Ps/100MSDCF/DSC00681.JPG \
  --reference /Users/makima/program/Ps/PhotoLibrary/参考/单图追色/奶油肤色参考.png \
  --output /Users/makima/program/Ps/PhotoLibrary/测试组/2025-09-29/成片/参考追色 \
  --name 另一组参考样片 --strength 0.85
```

输出原尺寸 16 位 TIFF（保留底稿 RGB 配置）、sRGB JPEG、三方脸部对比、皮肤选区检查图和特征 JSON。不会覆盖已有文件。只看试验结果可追加 `--diagnostic-only true`，不输出全尺寸成片。验证命令为 `swift test --disable-sandbox --filter ReferenceMatchTests`。

这次单图参考的人脸宽约 128 像素，适合估计色调，对肤质细节的参考有限。统计量也包含光线、妆容、相机显影和网络压缩的影响，不能反推出原作者的 PS 参数。当前只处理脸部与识别到的邻近皮肤，命令行试验仍集中在主脸；应用内现已提供参考导入、可编辑目标与逐张适配，身体皮肤候选可单独调色，尚未自动追色。

## 按帖子保存博主参考图

参考图库位于项目根目录的 `博主参考图库/光月大青蛙/`。每帖目录名采用「页面日期－标题－帖子ID末6位」，照片直接放在该目录并按原帖轮播顺序编号，`分析/` 独立保存选区、校验图和特征报告。网页下载文件按原字节保存，不重新压缩；它们属于平台提供的图片，不能代替相机原片。

本批按用户要求停止在已读取的 200 篇帖子：187 篇图文、2190 张图，以及 13 篇视频来源记录。`index.html` 可搜索帖子、按肤色明度和背景彩度筛选；`帖子特征汇总.csv` 与 JSON 提供每帖等权汇总，逐图数据在各帖的 `分析/特征.json` 内。

处理工具使用独立 Python 环境和原生本地分割模型：


## 人像工作流 · 第一阶段（2026-11-11）

本阶段接通「精细选区 → 独立肤色控制 → 单参考肤色目标 → 逐张适配 → 应用预览与导出」，并加入手动小瑕疵修复和纹理可控柔化。所有分析和处理都在本机完成。

### 精细区域和人物选择

添加图层时可选脖子、眼睛、眉毛、头发、牙齿候选、额头、画面左右脸颊、眼下、鼻侧和身体皮肤候选。眼睛、眉毛、头发、脖子沿用 FaceParsing 语义类别；牙齿候选取口腔内部的明亮低彩度像素，不把口腔整体当作牙齿。

额头、脸颊、眼下和鼻侧是由 Vision 双眼关键点推导的柔边区域，随双眼倾斜旋转，并与语义皮肤相交。它们是可修正的解剖位置引导，并不判断哪处存在瑕疵。刘海、闭嘴、遮挡时，对应区域可以为空；不会为了填满区域而选入头发或服装。

面部图层可选择「全部人物」或某一人物。人物按画面从左到右编号，不代表跨照片身份；相邻人脸解析结果通过空间归属隔离，避免一个裁切框包含另一张脸时两人一起调整。位置接近、严重遮挡或模型漏检仍需人工核对。

身体皮肤候选同时使用本张主脸的 Lab 色差、人物蒙版、服装与头部排除、人体姿态肢体走廊。相似肤色的服装、薄纱和袜子仍可能误入，姿态不可靠时也可能漏掉皮肤。此选区明确标为「候选」，可以用画笔补选、擦除，不默认执行自动精修。身体皮肤当前不提供按人物独立选择。

### 肤色、纹理和面部光影

选择皮肤类图层后，右侧出现独立控制：

- **白皙程度**：在 Lab 中使用单调明度曲线，保留黑白端点与扩展高光，不用平移曝光代替所有肤色提亮。
- **减少黄感**：限制 b* 调整，在深阴影与高光减弱。
- **肤色均匀度**：减轻局部色度变化，在检测到的脸颊区域减少处理，避免一起抹掉自然红润。
- **血色保留**：适度补充低、中彩度肤色，减少提亮后灰淡的观感。
- **脸颊红润**：只在相应人物的脸颊引导区改变 a*，可增加或减少。
- **皮肤柔化／纹理保留**：分别控制中频粗糙感与高频细节；跨边缘色差较大时抑制混合。
- **细节回补**：在白皙、参考适配和柔化之后补回损失的高频纹理；强边缘和高光处自动收敛，避免锐化光晕。旧项目默认 0，不改变已有输出。
- **边缘保护**：让白皙、去黄和红润在发丝、鼻翼、唇缘等高反差边界处收敛，减少亮边。旧项目默认 0。

以上仍受图层蒙版、画笔、羽化、不透明度与高光保护约束。眼下、鼻侧和左右脸颊可分别建层，用曝光、明度混合做局部减淡加深。眼睛、嘴唇、牙齿候选可分别建层微调。嘴唇图层的「唇部优化」会提亮暗唇、增加红润、减少黄感并淡化细唇纹，保留唇缘和光泽，可与「唇色自然化」叠加。没有自动判断「痘／痣／雀斑／腮红」，也没有默认的瘦脸、五官重塑。

### 手动小瑕疵修复

在右侧展开「手动小瑕疵修复」，开启点按模式。先点击干净皮肤取样，再点击小瑕疵；Option 点按重新取样。黄色圆环标示取样位置，可调笔刷大小。

修复使用取样位置的高频纹理和目标位置的低频光影，柔边合成，适合小痘点、小瑕疵，不是自动内容生成或大面积去物。取样和目标需离边缘留出完整笔刷半径。每次点按可撤销、重做，也可以清除本张全部修复点。修复在基础调色前执行，预览和全尺寸导出使用相同坐标与算子。

修复点保存在各自照片中；同步调色保留接收照片自己的修复点，自定义预设不带修复坐标。

### 参考肤色模板

1. 右侧展开「参考肤色模板」，导入 JPEG、PNG、TIFF 或已有模板 JSON。参考图始终读取所选成片，不升级到同名 RAW；提取面积最大的人脸。
2. 编辑名称、场景分组、目标亮度 L*、红润 a*、黄感 b*、允许亮度与色彩变化上限，选择保留明暗层次与脸颊保护。
3. 点击「应用当前」或「逐张应用全部」。每张照片、每位检测到的人物按自身处理后的像素重新计算，复制的是外观目标，计算量不固定。
4. 已应用区域可分别设置追色强度、借鉴亮度与借鉴色彩，选择作用人物、是否包含模型识别到的脖子。亮度或色彩为零时，该分量不追色。
5. 点击「画笔修正参考作用区域」直接补选、擦除追色蒙版。画笔修正仅随本张照片保存；同步时保留相同模板下接收照片自己的修正，不复制其他照片的笔画。
6. 点击「检查应用效果」查看每位人物实际的 L* 前后值、有效强度和自动回调信息。预览与导出也会执行同样的检查。目标照片没有可靠人脸或采样不足时报告错误，不生成未经分析的自动结果。
7. 「导出模板 JSON」保存参考特征、目标和限制，可再次导入；也随项目自动保存。编辑模板库不改变已应用照片的目标快照，需要再次应用。

参考特征保存 Lab 分位分布、有效采样数、人脸像素宽度和皮肤高光溢出比例。小脸、采样少、参考高光溢出时提示并降低权重；不提取或迁移参考纹理。每次适配限制明度、色彩变化量，检查合成后的高光溢出与明暗跨度；未通过则降低强度，仍不能满足限制时保留该人物原效果。脸颊保护会降低整个追色调整在脸颊的作用，后续可再建脸颊图层微调。

处理顺序为：手动修复 → 基础调色 → 普通调整图层 → 参考肤色适配。参考肤色目标根据前面步骤后的图像重新计算，因此改变前置图层也会触发重新适配。参考效果开关可使用追色强度归零或「移除」，原图按钮仍显示完整原始效果。

当前仍是单参考肤色闭环。后续小版本已加入可选的自动基础曝光、中性色偏色分析，以及单人照片的脸颈／手部候选区域协调，见下节。**镜头与水平校正、独立 RAW 降噪、多参考图自动分组归纳、人物／背景联合追色、唇肤和脸颊相对目标、自动瑕疵建议、可编辑曲线及完整 HSL／三向色彩控制尚未实现。** 不自动判定压缩程度、遮挡类型、蒙版准确性或纹理损失。

## 自动基础校正与身体肤色协调 · 0.3.1

本次针对实际对比里「欠曝原片只做肤色追色后仍偏暗」「脸提亮后与双手色差明显」两处补齐。

右侧「自动基础校正」可开启逐张自适应曝光、调整强度和脸部基础亮度，并选择逐张启用全部照片。它保存目标与上限，各张照片重新计算：先按全图统计提供至多 0.6 EV 的明暗补偿，再按主脸亮度对人物区域补光，默认人物上限 2.5 EV。两者使用固定黑白端点的单调色调曲线，改变 Lab 明度、保留色度；这里的 EV 是曲线补偿量，不是直接线性放大所有像素。已处于目标亮度以上的人像不会再自动提亮。

「分析校正建议」显示全图补偿、人物补光及实际脸部亮度前后值。偏色校正默认关闭；用户开启后，只在图中有足够明亮、低彩度的中性色候选时计算小幅 a*／b* 补偿，最多分别 2、3 Lab 单位。中性色不足时跳过并提示。它不能判断暖光是不是用户要保留的氛围，仍可关闭或用手动白平衡调整。

参考肤色的「协调身体肤色」会以适配后的本张脸部为依据，逐块统计身体皮肤候选，分别协调明度和色彩。将比脸部暗超过 3 L* 的身体皮肤适度提亮，并保留自然受光较亮的皮肤；允许一定红润和 1.5 b* 的黄感差异，只有超出容差才调整，单次明度变化上限 10 L*、色彩变化上限 10。身体区域保留原有色度跨度；强度可单独控制，每块区域检查高光和明暗跨度，失败时减弱或跳过。

身体候选在原有姿态、肤色、人物和服装限制之外，加入本地 Vision 手部关键点。可靠手部位置允许更宽的肤色色差，避免跨胸、伸出的手因光照和服装误分而完全漏选；仍受人物边界与肤色特征约束。自动协调会排除碎片、过大的连通区域和缺乏核心采样的区域。候选不等于准确皮肤分割，可点击「查看／修正身体候选」检查并补选或擦除；笔画仅保存于各自照片，预设不带坐标，批量同步保留接收照片自己的修正。

自动身体协调当前限于单人照片。多人照片仍可逐人追脸部肤色，但身体不自动配对到身份，会提示通过身体图层手动处理。首版身体选区的可用性依赖手部关键点、光照与衣着；戴手套、遮挡、模糊和肤色相近的袖口需人工检查。

新建的参考应用默认身体协调强度为 0.8；旧项目中缺少该字段时保持关闭。自动基础校正在旧项目中保持关闭，需要用户启用。参考追色强度归零时，其身体协调一并关闭。

新的合成顺序为：手动修复 → 自动基础校正（可选）→ 手动基础调色 → 调整图层 → 脸部参考适配 → 身体肤色协调。预览和全尺寸导出使用同一处理链。本轮过程文件和旧版对比输出已清理，只保留最终成片。

## 嘴唇优化与皮肤细节 · 0.3.2

本轮针对「放大后皮肤偏软」「暗片嘴唇发灰、唇纹明显」两处补齐。三项能力都默认关闭，旧项目 JSON 缺少字段时保持原有输出。

**唇部优化（嘴唇图层）**：在 Lab 中提亮较暗的唇部，增加 a* 红润、减少 b* 黄感，并用细尺度高斯差分降低唇纹对比。唇缘由宽尺度色度差定位并保留，镜面高光不参与柔化。它只通过嘴唇蒙版生效，适合先用它统一唇色，再用「唇色自然化」微调；两者可叠加。演示参数为 0.60。

**细节回补（肤色图层）**：在白皙、均匀度、柔化和参考适配之后，把 0.00025 × 长边尺度的高频细节按比例加回 Lab 明度。处理限定在皮肤蒙版内，L* 高于约 82 后收敛，局部梯度超过阈值时不放大，避免发丝、鼻翼和唇缘出现锐化光晕。建议 0.10–0.25；本轮样片使用 0.20。

**边缘保护（肤色图层）**：白皙、去黄、血色和红润乘以一个由细尺度 Lab 色差得到的边缘权重，使发丝、鼻孔和唇缘附近的高反差像素少受影响。旧项目默认 0；本轮样片使用 1.0。

本轮同时把演示参数从「柔化 0.30／纹理保留 0.75」调整为「柔化 0.20／纹理保留 0.85」，并加入细节回补。实测 DSC00681 脸颊 Laplacian 从 4.66 回到 5.24（原片 5.19），背景保持 4.48 不变；DSC00753 从 5.09 提到 5.95。背景、头发和衣物未被处理。

**跨照片灰感补偿**：大幅度提亮会保留 Lab 的 a*/b*，明度上去后皮肤容易显灰；参考追色又受追色强度、参考可靠性、最大色差和脸颊保护的共同限制，暗片最终常达不到模板的色度。现在参考适配在合成后实测脸部 C*，如果低于模板目标超过 0.2，就在脸部皮肤蒙版内按差额放大 a*/b*，并把 b* 向模板黄度补足，上限为模板 C* 的 1.05 倍；每次应用后重新检查高光溢出和 p10–p90 明暗跨度，不通过则减半重试。该补偿只补不足，不压低本来更饱和的照片，因此 DSC00681 不受影响，DSC00753 会从 C*≈19.1 提到约 20.7–21.0，色相从约 28° 回到 33–34°。新应用默认 0.8，可在「灰感补偿」滑块调整；旧项目缺少字段时保持关闭。

自动适配目前仍是「逐张测量 + 目标闭环」，不是跨照片学习：模板目标固定，每张照片按自身脸部亮度和色度重新计算，超出模板上限时只能部分接近。后续若要进一步消除不同光线的差异，可把模板目标按场景曝光做相对缩放，或用多张同场景照片归纳目标；本轮未实现。

三阶段成片（DSC00681）保存在 `.build/portrait-workflow-v3/final/`（当前阶段 / 唇部优化 / 皮肤优化）。中间过程图、蒙版、对比板、旧版成片和参考分析的临时输出已清理，只保留这 3 张成片。测试总数 52 项。

## 独立唇色与最终肤色协调 · 0.3.3

嘴唇图层新增「唇部明亮度」「唇色偏移 · 粉／珊瑚」「唇色浓淡」「唇纹柔化」四项独立控制。亮度在 Lab 中单独改变 L*，色调以旋转色度方向处理，浓淡缩放色度，柔化只减弱细尺度明度变化。唇缘和高光处减弱处理；柔化默认关闭。旧版的两个组合滑杆保留在折叠项中，旧项目缺少新字段时保持原有输出。

新建嘴唇图层默认「保留原色 · 自动协调」，也可选择手动、自然粉、柔玫瑰、暖珊瑚或借鉴参考唇色。自动模式在普通图层、参考肤色和身体协调之后执行，按每位人物的最终肤色与当前唇色重新计算，保留上下唇及唇内明暗差；仍受图层开关、人物选择、画笔、羽化、不透明度、高光保护及混合模式约束。它不是诊断原片偏色或识别口红品牌。

自动协调使用相对唇肤亮度范围，保留原色模式不旋转唇色。风格模式限制自动色相变化为 ±18°，色度比例为 0.75–1.20，亮度变化为 −4 至 +6 L*，之后再应用强度和用户的独立微调。手动微调可叠加在自动结果上。嘴唇采样不足或所选人物不存在时提示错误，可关闭该层或选择手动模式；不默默套用固定玫瑰色。

重新导入参考成片时，模板会尝试保存同一人脸的唇肤亮度差、色相差、彩度比及可靠程度；嘴唇采样少时降低权重，无法采样则不保存唇色目标。旧模板需要重新导入参考图才能增加唇色特征。参考模式借用当前照片已经应用的模板快照；没有唇色目标时界面提示，非零强度渲染会报错。参考目标不包含纹理迁移。

## 独立浅粉唇色与自动瑕疵候选 · 0.3.4

### 唇色参考独立保存

嘴唇图层可以单独使用模板库中的参考，不再要求与脸部肤色使用同一张参考图。导入参考、选中模板后，在嘴唇图层选择「借鉴参考唇色」，点击「将所选参考模板用于唇色」；保存的是目标快照，编辑模板库不会改动已应用照片。

新提取的唇色目标同时保存实际 Lab 明度、红绿与黄蓝分量和参考脸部明度。参考模式用实际唇色约束彩度，避免参考皮肤很淡时，唇肤彩度比在目标照片上放大唇色；明度只按最终脸部亮度做最多 ±3 L* 的场景补偿，再逐张计算受限变化。新目标的自动提亮上限为 8 L*，旧模板没有绝对外观目标时仍沿用原先的相对目标和 6 L* 上限；最终仍乘以参考可靠程度与用户强度，并保护高光。人工亮度、色调、浓淡与柔化仍可单独控制。

用户选定的 1 号「自然浅粉」模板来自归档原始参考图，超分只用于观看，不参与取色。681 和 735 共用相同唇色目标与强度，人工亮度／色调／浓淡偏移均为零；两张实测分别计算约 +3.02 和 +0.17 L* 的唇部明度调整。原有肤色与高光参数保留，仍有之前按照片设置的高光差异，不能将整套样片参数称为完全自动调色。成品位于 `成片/1号自然浅粉/`，可导入的参考模板位于 `参考方案/1号自然浅粉-唇色模板.json`。

### 自动瑕疵候选与修复

右侧新增「自动瑕疵候选与修复」。点击「分析本张照片」后，本机根据各张照片的实际像素和逐人人脸蒙版重新计算小红点、深色点，并为每个候选在本张照片附近寻找干净的取样区；不使用针对 681 或 735 编写的固定坐标。

- 分析采用局部 Lab 色彩／明度差、连通区域尺寸与形状筛选，排除较强光影边缘、眼睛、眉毛、嘴唇、头发、眼下及鼻侧引导区域。小于 120 像素宽的人脸跳过并提示。
- 候选是局部异常点，不是经过训练的痘痘分类模型。评分只表示规则排序，不能当作概率；仍可能误选痣、雀斑、妆容及阴影，或者漏掉低对比瑕疵。没有候选时不强制生成修复点。
- 图上显示对应编号，可定位放大、逐个勾选或排除。只有评分至少 0.8 且找到干净取样区的红色候选默认勾选；深色点默认不选。分析不会改变照片，点击「修复所选」才应用。
- 修复复用现有的低频光影／高频纹理合成，支持撤销与重做。没有合适取样区的候选不能勾选，可以继续使用手动取样修复。
- 切换照片、撤销／重做或改变修复点后清除旧候选；异步结果只接受当前照片及匹配的修复快照，避免把过期结果用到另一张图。
- 应用后的修复点保存在各自照片中；预设不保存坐标，批量同步保留接收照片自己的修复点。当前界面是逐张分析与确认，没有无人值守的批量去痘。

验证覆盖合成小红点与深色点、宽面积腮红与蒙版外物体的排除、平坦皮肤不生成候选、不同图片位置重新计算、自动取样有效性、深色点不默认推荐，以及照片归属、过期分析保护、撤销、同步和预设行为。实际照片另做候选位置检查；自动测试不代替人工看图。

## 快速修图入口与逐张批处理 · 0.4.0

默认界面改为「快速修图」：导入照片 → 选择肤色风格 → 一键自动修图 → 原图／效果对比 → 少量观感微调 → 导出。默认不显示图层、Lab 目标、蒙版和修复半径；需要局部画笔、图层和专业参数时，切换顶部「高级编辑」。快速模式保留提亮程度、肤色均匀、皮肤柔化、唇色及强度，导入参考图属于可选步骤。

「一键自动修图」将自动补光、肤色目标、身体协调、唇色目标、瑕疵分析和高分红点修复串在一起。内置自然通透／白皙红润是外观目标，不是从某张测试照片复制曝光。自然浅粉来自用户选定的 1 号参考，统计随应用打包；原色模式关闭肤色追色，只保留补光、可选的均匀与柔化及身体协调。深色点和其他非推荐候选不自动处理，可在「检查局部细节」中确认。

「按此风格处理全部」为每张照片单独分析和取样，应用相同目标与偏好。处理先验证像素流程，成功后一次提交；取消不留下半套结果，整次操作可以撤销。单张失败会保留原编辑，并报告文件名。处理中用户改动了某张照片时跳过覆盖。重新处理替换快速流程图层，避免重复叠加；保留本张修复点和对应皮肤／唇部画笔修正。原有其他调色会被重新生成，按钮提示这一行为，撤销可恢复处理前状态。

快速模式中的观感滑杆在已处理照片上直接预览。自动修复红点选项在下一次自动处理时生效；关闭它不会撤销已应用的修复点。效果和强度偏好随项目保存。高分红点仍是规则筛选结果，不代表医学或语义分类；当前没有可靠区分所有痘、痣和妆容的模型。

GUI 与 `PortraitRetouch --quick` 共用 `PortraitIntent.settings` 生成处理参数，使用同一个 ColorEngine 预览与导出。命令行可用于跨组验收：

```sh

  --input 100MSDCF/DSC00260.JPG --quick --skip-tiff \
  --output 成片/跨组反馈修订-4张 --qa .build/feedback-qa-2026-11-12/final/DSC00260 --name 反馈修订
```

额外输出逐张自动补光、肤色追色、唇色适配和瑕疵分析 JSON，便于核对同一目标下的实际变化。测试覆盖重复处理不叠加、模板与照片数据归属、偏好保存、取消和整组撤销，并以实际的 681、735 验证批处理。

## 跨组反馈修订 · 0.4.2 · 2026-11-12

本次针对 260 的灰感、372 的红点漏修、1063 的脸颈和手部选区，以及 1197 的唇色与小红点调整共用算法。四张仍使用相同 `PortraitIntent`，没有写入文件名判断、手绘补选或逐张曝光／色彩偏移。

- 增加脸颈可见皮肤补选：以本张解析皮肤为种子，在局部范围内按本张肤色连接扩展，排除衣服、眼眉、嘴唇与手部；距离原语义边界越远，补选越弱。手部不会被当作脸颈重复处理。此步骤仅恢复可见皮肤候选，不生成被头发完全遮住的皮肤。1063 的发丝、耳部道具与阴影交界仍需放大检查。
